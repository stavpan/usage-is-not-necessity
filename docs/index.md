# world-impact

**An uncertainty-aware, multi-criteria basis for ranking world-historical
developments.**

Most claims that "X was a turning point" are unfalsifiable prose. This project
makes them falsifiable: it codes documented developments against 18 outcome
domains named to their custodian datasets, then asks what structure that coding
actually supports — and reports the answer as an *interval plus a Pareto
frontier*, never as a single league table, because the arithmetic says a single
league table does not exist.

## Read in this order

1. **[Methods](methods.md)** — what the instrument does, stage by stage, and
   what it cannot do.
2. **[Decision log](decisions.md)** — fifteen decisions including six
   retractions. Read this before trusting anything in the methods.
3. **[Literature review](literature.md)** — what exists already (Morris's social
   development index, the Seshat databank, CHAT, SMAA, Leontief linkage) and
   what is actually new here.

## The two results worth knowing

**The rubric saturates.** With four categories per item, the instrument cannot
distinguish "transformed the world" from "transformed the world enormously". No
acceleration claim is made anywhere in this repository because the instrument
cannot support one. This is demonstrable via the test-information function, and
it is why the report carries a limitations section automatically.

**There is no league table.** Ranking depends on which outcomes you weight and
which norm you use to combine them. Both are normative choices. So the deliverable
is a Pareto frontier (which needs no weights at all) plus SMAA rank-acceptability
distributions over the space of legitimate weightings — not a list.

## Quickstart

```bash
pixi install
pixi run validate     # schema + citation completeness; fails loudly
pixi run all          # gates, analysis, figures, report
```

## Where the numbers live

`reports/results.json` (machine-readable), `reports/report.md` (generated, with
limitations), `figures/*.svg` (generated). All of it is regenerated by
`pixi run all` and CI runs the pipeline twice and diffs the output, because a
pipeline that is not bit-reproducible under a fixed seed is a sample, not a
result.
